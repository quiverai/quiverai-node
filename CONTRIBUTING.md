# Contributing to This Repository

Thank you for your interest in contributing. Most of this repository is generated by [Speakeasy](https://www.speakeasy.com) from the QuiverAI OpenAPI document, so where a change belongs depends on what it touches.

## What can be changed here

Files marked `Code generated by Speakeasy. DO NOT EDIT.` are overwritten on every generation, as are `docs/`, `package.json` and the marked sections of `README.md`. Changes to them will be lost. These parts of the repository are maintained by hand and pull requests against them are welcome:

| Path | Purpose |
| --- | --- |
| `gen.yaml` | Generator options, including extra `package.json` fields and scripts |
| `.speakeasy/workflow.yaml`, `.speakeasy/*.overlay.yaml` | Generation workflow and OpenAPI overlays (naming, forward compatibility) |
| `src/hooks/` (except `hooks.ts` and `types.ts`) | Request lifecycle hooks, registered in `src/hooks/registration.ts` |
| `src/helpers.ts` | Hand-written helpers, published as `@quiverai/sdk/helpers` |
| `tests/` | Tests that run against the built SDK with a mocked HTTP client |
| `examples/*.example.ts` (new files) | Runnable examples |
| `README.md` outside the `<!-- Start ... -->` / `<!-- End ... -->` blocks | Hand-written documentation |
| `.github/workflows/ci.yaml` | Lint, build, test and example typecheck |

Changes to the API surface itself (operations, models, method names) belong in the OpenAPI document or in an overlay, and reach the generated code through the next generation run.

## Local development

```bash
npm ci
npm run lint
npm run build
npm test
```

`npm test` runs against `dist/`, so build first. To typecheck the examples:

```bash
npm install --prefix examples
npx tsc -p examples/tsconfig.json
```

## How to Report Issues

If you encounter any bugs or have suggestions for improvements, please open an issue on GitHub. When reporting an issue, please provide as much detail as possible to help us reproduce the problem. This includes:

- A clear and descriptive title
- Steps to reproduce the issue
- Expected and actual behavior
- Any relevant logs, screenshots, or error messages
- Information about your environment (e.g., operating system, software versions)
    - For example can be collected using the `npx envinfo` command from your terminal if you have Node.js installed

## Issue Triage and Upstream Fixes

We will review and triage issues as quickly as possible. Bugs in generated code are fixed in the upstream OpenAPI document or generator configuration, and the fix is included in the next generation of the SDK.
